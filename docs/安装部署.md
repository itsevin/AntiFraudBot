# 📦 安装与部署

[文档中心](README.md) · [English](en/installation.md) · [配置参考](配置参考.md) · [安全部署](安全部署.md)

本指南提供一套可复现的 AntiFraudBot 安装流程。项目后端沿用 Poetry 管理依赖；请不要把项目依赖直接安装到全局 Python 或 Conda base 环境。

## 1. 环境要求

| 组件 | 建议版本 | 用途 |
|---|---|---|
| Python | `3.9–3.12` | NoneBot2、FastAPI 和数据库后端 |
| Poetry | `2.x` | 独立虚拟环境与依赖锁定 |
| Node.js | `22+` | Vue/Vite 前端构建 |
| Git | 最新稳定版 | 获取代码与版本管理 |
| OneBot 11 实现 | 按实现文档 | 连接 QQ 与 NoneBot2 |

推荐使用 [NapCat](https://napneko.github.io/) 等仍在维护的 OneBot 11 实现。具体登录、协议和风控要求以对应项目文档为准。

## 2. 获取代码

```bash
git clone https://github.com/itsevin/AntiFraudBot.git
cd AntiFraudBot
```

确认当前目录包含 `pyproject.toml`、`poetry.lock`、`src/` 和 `source/`。

## 3. 安装后端依赖

```bash
poetry install
poetry env info
```

`poetry env info` 应显示 Poetry 自己的虚拟环境路径。之后所有 Python 命令都使用 `poetry run ...`，无需激活或修改 Conda 环境。

验证依赖：

```bash
poetry check --lock
poetry run python -m pip check
poetry run nb --help
```

## 4. 创建配置文件

PowerShell：

```powershell
Copy-Item .env.example .env
Copy-Item .env.prod.example .env.prod
```

Linux / macOS：

```bash
cp .env.example .env
cp .env.prod.example .env.prod
```

必须设置一个至少 12 位、不是常见默认值的后台密码：

```dotenv
WEB_ADMIN_PASSWORD=CHANGE_ME_USE_AT_LEAST_12_CHARACTERS
```

建议保持 Web 后台只监听本机：

```dotenv
WEB_HOST=127.0.0.1
WEB_PORT=8000
WEB_CORS_ORIGINS=["http://127.0.0.1:8000","http://localhost:8000"]
```

AI 与阿里云 URL 检测都是可选功能。未配置密钥时，请保持字段为空并关闭相关功能，而不是填写演示密钥。

完整说明见 [配置参考](配置参考.md)。

## 5. 初始化数据库

```bash
poetry run python scripts/init_database.py
```

脚本会：

1. 创建 `data/data.db`；
2. 检查当前表结构；
3. 迁移旧版 `data/data.json` 中可映射的群聊和私聊配置；
4. 导入 `source/quiz_bank.json`；
5. 导入 `source/keyword.txt`；
6. 在缺少 `.env.prod` 时从安全模板创建本地配置。

运行后可以执行只读检查：

```bash
poetry run python scripts/check_db.py
```

数据库、JWT 密钥和本地配置都被 Git 忽略，不应进入仓库。

## 6. 构建 Web 前端

```bash
cd src/web/frontend_v2
npm ci
npm run build
cd ../../..
```

生产文件生成在 `src/web/frontend_v2/dist/`，该目录不会提交到 Git。每次更新前端代码后都应重新构建。

## 7. 配置 OneBot 11

AntiFraudBot 通过 NoneBot2 的 OneBot V11 适配器连接机器人实现。通常需要在 OneBot 实现中配置反向 WebSocket，目标指向 NoneBot 服务。

默认 NoneBot 地址：

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

实际路径和鉴权方式可能因 OneBot 实现版本不同而变化。不要把 OneBot Token 写入仓库或截图。

## 8. 启动

```bash
poetry run nb run
```

启动日志应包含：

- NoneBot 初始化成功；
- OneBot V11 适配器已加载；
- `nonebot_plugin_orm` 已加载；
- `src/plugins` 中的插件被发现；
- Web 管理后台线程已启动。

访问：

| 服务 | 默认地址 |
|---|---|
| NoneBot / OneBot | `http://127.0.0.1:8080` |
| Web 登录页 | `http://127.0.0.1:8000/#/login` |

## 9. 首次验证

1. 使用配置的管理员密码登录 Web 大屏；
2. 在 QQ 中发送 `帮助`；
3. 运行一次 `签到` 或 `反诈答题`；
4. 用测试消息验证关键词提醒；
5. 确认 `data/data.db` 已生成；
6. 确认 `git status` 没有显示 `.env.prod`、数据库或 JWT 密钥。

项目自检：

```bash
poetry run pytest -q
poetry run ruff check src scripts tests
poetry run python scripts/check_open_source.py
```

## 10. 更新项目

更新前先备份本地数据库和配置。不要覆盖 `.env.prod`。

```bash
git pull --ff-only
poetry install
poetry run python scripts/init_database.py

cd src/web/frontend_v2
npm ci
npm run build
cd ../../..
```

随后重新启动机器人并完成首次验证清单。

## 11. 公网部署

不要直接把 `WEB_HOST` 改为 `0.0.0.0` 后裸露端口。推荐：

```text
Internet → HTTPS reverse proxy → 127.0.0.1:8000 → AntiFraudBot Web
```

至少需要：

- HTTPS；
- 强管理员密码；
- 明确的 `WEB_CORS_ORIGINS`；
- 防火墙或安全组规则；
- 反向代理级速率限制；
- 定期备份和日志脱敏。

详细要求见 [安全部署](安全部署.md)。

## 12. 常见故障

### `nb` 命令不存在

确认使用了项目 Poetry 环境：

```bash
poetry install
poetry run nb --help
```

不要改用全局 `pip install nb-cli` 规避依赖问题。

### 启动时提示“检测到旧的项目格式”

这是 `nb-cli 1.7` 对 `[tool.nonebot]` 配置写法的迁移提示，不代表数据库、插件或业务代码损坏。当前项目使用的 NoneBot2 运行时仍要求列表格式；直接执行 `nb upgrade-format` 会与 Pydantic 1 组合不兼容，等价的手动迁移也会导致 NoneBot 无法加载 `plugins`。

因此，在上游运行时与 CLI 同时支持新格式前可以安全忽略该提示。请不要为了消除提示而全局安装、强制升级依赖或直接改写 `pyproject.toml`。

### Web 页面显示“正在升级中”

说明 `dist/` 尚未构建：

```bash
cd src/web/frontend_v2
npm ci
npm run build
```

### 登录返回 503

`WEB_ADMIN_PASSWORD` 未配置、少于 12 位或使用了常见默认密码。修改 `.env.prod` 后重启。

### 登录返回 429

同一来源短时间内失败次数过多。等待限制窗口结束，并检查密码配置。

### 题库为空

确认 `source/quiz_bank.json` 存在，然后重新运行：

```bash
poetry run python scripts/init_database.py
```

### AI 或 URL 检测不可用

确认对应开关、服务地址、模型名、密钥权限、余额和网络连通性。不要在 Issue 中粘贴完整密钥或原始私聊内容。
